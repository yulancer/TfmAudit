# TfmAudit Context

## Purpose
Утилита находит в графе зависимостей NuGet пакеты, которые под конкретным таргетом проекта
отдают ассеты более раннего поколения (`lib/net6.0` под `net8.0`, `lib/net8.0` под `net10.0`),
и объясняет оператору, какую прямую зависимость надо обновить, чтобы этот слой ушёл.

Задача возникла при переводе сервисов с net6 на net8: сам проект пересобирается под новый таргет,
а граф зависимостей — нет, и NuGet молча подставляет ассеты предыдущего поколения.

## Tech Stack
- C# 10, .NET 6.0 (`net6.0`) — консольное приложение
- Ноль `PackageReference`: только BCL из состава net6 (`System.Text.Json`, `HttpClient`,
  `System.IO.Compression`, `System.Xml.Linq`)
- `<RollForward>LatestMajor</RollForward>` — бинарь запускается и на более новых рантаймах
- HTML-отчёт: vanilla JS + inline SVG, без внешних ресурсов; шаблон лежит в ресурсах сборки

## Project Conventions

### Code Style
- Файловые namespace (`namespace TfmAudit.Analysis;`), `Nullable` и `ImplicitUsings` включены
- `TreatWarningsAsErrors=true`; сборка держится на нуле предупреждений
- Публичные типы и неочевидные места комментируются по-русски, XML-doc в стиле `/// <summary>`
- Никаких сокращений в именах; вместо `var x` — осмысленные имена
- Комментарий объясняет «почему», а не «что»: если код читается сам, комментария не нужно

### Architecture Patterns
- Слои разделены по папкам и не знают друг о друге больше необходимого:
  `Model` (чтение assets, парсер TFM) → `Analysis` (классификация, граф, атрибуция)
  → `Reporting` (шесть форматов вывода); `NuGet` подключается опционально и только обогащает
  результат анализа советами по версиям
- Анализ не обращается в сеть: `--online` — отдельный проход, дописывающий `UpgradeAdvice`
  в уже готовую модель. Отчёт валиден и без него
- Никакой зависимости от `NuGet.*` пакетов: логика выбора ассетов и семантика версий
  реализованы явно, чтобы утилита оставалась одним файлом без внешних ссылок
- Правила общие для любых TFM, а не захардкожены под net6/net8

### Testing Strategy
- Автотестов пока нет. Проверка — прогон на реальном `samples/project.assets.json`
  (мультитаргет `net6.0` + `net8.0`, 231 узел) со сверкой находок с ручным разбором JSON
- HTML-отчёт проверяется рендером в headless-браузере: отсутствие ошибок в консоли,
  корректность на ширине 400/768/1440, светлая и тёмная темы
- Любое изменение правил классификации требует прогона на примере и сверки гистограммы TFM

### Git Workflow
- Ветка на изменение, имя совпадает с `change-id` из OpenSpec
- Коммит описывает поведение, а не файлы

## Domain Context
- **Ассет** — папка внутри NuGet-пакета, из которой restore берёт библиотеку для данного таргета:
  `lib/<tfm>/`, `ref/<tfm>/`, `runtimes/<rid>/lib/<tfm>/`, `build/<tfm>/`
- NuGet выбирает **наибольший TFM ассета, не превышающий таргет**. Поэтому пакет с папками
  `net6.0` и без `net8.0` под таргетом `net8.0` отдаёт net6-сборку без ошибок и предупреждений
- `project.assets.json` — результат восстановления; в секции `targets/<tfm>` уже записаны
  **выбранные** ассеты, поэтому анализатор читает факт, а не пересчитывает правила совместимости
- Мультитаргетность и условные ссылки в csproj — норма. Расхождения между таргетами
  находками не считаются
- `netstandard2.x` формально совместим с любым современным .NET: это признак старого пакета,
  а не поломка
- Транзитивную версию напрямую поднять нельзя (кроме явного пина), поэтому обновлять надо
  прямую зависимость, которая её тянет

## Important Constraints
- Утилита должна собираться и работать под **net6.0** — это требование заказчика
- Внешние NuGet-пакеты запрещены
- Офлайн-режим обязателен: без сети утилита обязана давать полный анализ
- Отчёт должен объяснять находку так, чтобы её можно было проверить руками: с путём ассета
  внутри пакета и цепочкой зависимостей
- Формулировки в отчётах не должны обещать больше, чем даёт анализ: если находка достижима
  из нескольких корней, так и надо написать

## External Dependencies
- NuGet V3 API (`index.json` → ресурс `PackageBaseAddress/3.0.0`) — только в режиме `--online`
- `NuGet.config` пользователя и репозитория — источник адресов фидов и учётных данных
- Graphviz (`dot`) и Visual Studio — внешние средства просмотра форматов `--dot` и `--dgml`
