## Purpose
Классификация пакетов по тому, насколько выбранный для них ассет отстаёт от таргета: определение
уровня находки, объяснение на естественном языке и подсказки о пакетах, которые на современном
рантайме вообще не нужны.

## ADDED Requirements

### Requirement: Находка при отставании ассета в том же семействе
Анализатор ДОЛЖЕН сообщать находку, когда выбранный ассет относится к тому же семейству, что и
таргет, но к более раннему поколению. Уровень ДОЛЖЕН быть «ошибка» при отставании на два и более
мажорных поколения и «предупреждение» при отставании на одно.

#### Scenario: net6-ассет под таргетом net8
- **GIVEN** таргет `net8.0` и пакет, отдающий `lib/net6.0/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «ошибка» с отставанием в два мажорных поколения

#### Scenario: net8-ассет под таргетом net10
- **GIVEN** таргет `net10.0` и пакет, отдающий `lib/net8.0/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «ошибка» — правило работает без привязки к конкретным версиям

#### Scenario: net7-ассет под таргетом net8
- **GIVEN** таргет `net8.0` и пакет, отдающий `lib/net7.0/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «предупреждение»

#### Scenario: Ассет ровно под таргет
- **GIVEN** таргет `net8.0` и пакет, отдающий `lib/net8.0/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** находка не формируется, а пакет попадает в счётчик «ассет ровно под таргет»

### Requirement: Отдельный уровень для ассетов .NET Standard
Анализатор ДОЛЖЕН относить ассеты `netstandard2.x` под .NET-таргетом к уровню «информация»,
поскольку они формально совместимы, и к уровню «предупреждение» для `netstandard1.x`.
Анализатор ДОЛЖЕН уметь повышать `netstandard2.x` до предупреждения по настройке.

#### Scenario: netstandard2.0 — это информация, а не ошибка
- **GIVEN** таргет `net8.0` и пакет, отдающий `lib/netstandard2.0/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «информация» с пояснением, что совместимость сохраняется,
  но пакет собирался до появления текущего таргета

#### Scenario: netstandard1.x тянет за собой старые контракты
- **GIVEN** таргет `net8.0` и пакет, отдающий `lib/netstandard1.3/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «предупреждение»

### Requirement: Находка при ассете чужого семейства
Анализатор ДОЛЖЕН сообщать находку уровня «ошибка», когда под .NET-таргетом выбран ассет
.NET Framework или портируемого профиля — такое возможно только через `AssetTargetFallback`.

#### Scenario: Ассет .NET Framework под таргетом net8
- **GIVEN** таргет `net8.0` с включённым `AssetTargetFallback` и пакет, отдающий `lib/net472/Foo.dll`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «ошибка» с пояснением, что ассет подставлен через fallback
  и работает не гарантированно

### Requirement: Предупреждение о ссылках на сборки .NET Framework
Анализатор ДОЛЖЕН сообщать находку уровня «предупреждение», если у пакета под .NET-таргетом
заполнена секция `frameworkAssemblies`.

#### Scenario: Пакет требует сборку из GAC
- **GIVEN** таргет `net8.0` и пакет с `frameworkAssemblies: ["System.Configuration"]`
- **WHEN** анализатор классифицирует пакет
- **THEN** формируется находка уровня «предупреждение»

### Requirement: Ослабление уровня при устаревании только MSBuild-ассетов
Анализатор ДОЛЖЕН понижать уровень находки на одну ступень, если устарели только ассеты
MSBuild (`build/`, `buildTransitive/`, `buildMultiTargeting/`), а ассеты кода соответствуют таргету.

#### Scenario: Актуальный код и старые props
- **GIVEN** таргет `net8.0` и пакет с `compile: lib/net8.0/Foo.dll` и `build/net6.0/Foo.props`
- **WHEN** анализатор классифицирует пакет
- **THEN** уровень находки понижается на одну ступень относительно того, что дал бы разрыв TFM

### Requirement: Сигнал о включённом AssetTargetFallback
Анализатор ДОЛЖЕН сообщать по каждому таргету, включён ли для него `AssetTargetFallback`,
и перечислять его `imports`.

#### Scenario: Таргет с fallback на .NET Framework
- **GIVEN** таргет `net8.0` с `assetTargetFallback: true` и списком `imports` из net461…net481
- **WHEN** анализатор формирует результат по таргету
- **THEN** в отчёте появляется предупреждение, что несовместимые ассеты подставляются молча,
  без ошибки восстановления

### Requirement: Подсказки о пакетах, входящих в рантайм
Анализатор ДОЛЖЕН помечать находки для пакетов, чья функциональность входит в состав рантайма
начиная с некоторой версии, а также для контрактных пакетов эпохи .NET Standard 1.x, и
формулировать подсказку как гипотезу, а не как приказ.

#### Scenario: Пакет входит в состав рантайма
- **GIVEN** таргет `net8.0` и находка по `System.Text.Json 4.7.2`
- **WHEN** анализатор формирует находку
- **THEN** к ней добавляется подсказка, что пакет входит в рантайм начиная с .NET 6.0 и прямая
  ссылка, как правило, не нужна

#### Scenario: Старый контрактный пакет
- **GIVEN** таргет `net8.0` и находка по `System.Runtime 4.1.0`
- **WHEN** анализатор формирует находку
- **THEN** к ней добавляется подсказка, что это контракт эпохи .NET Standard 1.x, кода он не несёт
  и уйдёт сам после обновления виновника

### Requirement: Фильтрация находок
Анализатор ДОЛЖЕН поддерживать порог уровня, список игнорируемых пакетов (в том числе по префиксу)
и отбор таргетов, и ДОЛЖЕН применять их до формирования отчёта.

#### Scenario: Только ошибки
- **GIVEN** порог уровня «ошибка»
- **WHEN** анализатор формирует результат
- **THEN** в находки попадают только записи уровня «ошибка»

#### Scenario: Игнорирование по префиксу
- **GIVEN** список игнорируемых пакетов `Contoso.Platform.*`
- **WHEN** анализатор формирует результат
- **THEN** пакеты, чей идентификатор начинается на `Contoso.Platform.`, в находки не попадают

### Requirement: Честный расчёт эффекта обновления
Анализатор ДОЛЖЕН относить к «эксклюзивным» только те находки, которые достижимы ровно из одной
прямой зависимости, и НЕ ДОЛЖЕН представлять набор прямых зависимостей как минимальный набор,
закрывающий все находки, если находка достижима из нескольких корней.

#### Scenario: Находка достижима из двух прямых зависимостей
- **GIVEN** находка, достижимая и из `A`, и из `B`
- **WHEN** анализатор формирует рекомендации
- **THEN** находка не считается эксклюзивной ни для `A`, ни для `B`, а в сводке она попадает в
  число тех, что уйдут только после обновления всех виновников

#### Scenario: Приоритет обновления
- **GIVEN** несколько прямых зависимостей, ведущих к находкам
- **WHEN** анализатор формирует рекомендации
- **THEN** они упорядочены по числу эксклюзивных находок, а при равенстве — по общему числу
  затронутых находок
