## Purpose
Представление результата анализа в шести форматах: читаемый вывод в терминал, Markdown для
передачи команде, самодостаточный HTML с интерактивным графом, JSON для CI и файлы графа для
Graphviz и Visual Studio.

## ADDED Requirements

### Requirement: Проверяемость находки
Каждый отчёт ДОЛЖЕН показывать для находки путь выбранного ассета внутри пакета, чтобы вывод можно
было проверить руками по содержимому пакета.

#### Scenario: Находка с путём ассета
- **GIVEN** находка по пакету, отдающему `lib/net6.0/Foo.dll` под таргетом `net8.0`
- **WHEN** формируется любой из отчётов
- **THEN** в нём присутствует секция ассета и полный путь внутри пакета

### Requirement: Объяснение на естественном языке
Отчёт ДОЛЖЕН описывать каждую находку фразой, объясняющей, что произошло, без требования знать
внутренности NuGet, и ДОЛЖЕН соблюдать правила согласования русских числительных.

#### Scenario: Объяснение отставания
- **GIVEN** находка с отставанием ассета на шесть мажорных поколений
- **WHEN** формируется объяснение
- **THEN** оно читается как «это 6 мажорных поколений назад», а не «6 мажорных поколения назад»

### Requirement: Раздел «Что обновить»
Отчёт ДОЛЖЕН содержать список прямых зависимостей, ведущих к находкам, отсортированный по
влиянию, и ДОЛЖЕН отдельно указывать число находок, достижимых ровно из одной прямой зависимости,
и число тех, что достижимы из нескольких.

#### Scenario: Разделение гарантированного и условного выигрыша
- **GIVEN** результат, где 51 находка достижима из одного корня и 77 — из нескольких
- **WHEN** формируется раздел «Что обновить»
- **THEN** оба числа приведены явно, с пояснением, что вторая группа уйдёт только после
  обновления всех виновников

#### Scenario: Пометка project-ссылки
- **GIVEN** прямая зависимость, являющаяся `ProjectReference`
- **WHEN** формируется раздел «Что обновить»
- **THEN** она помечена как project-ссылка, и для неё не показывается совет фида

### Requirement: Консольный отчёт
Утилита ДОЛЖНА печатать отчёт в стандартный вывод с ANSI-цветами и ДОЛЖНА отключать цвета при
перенаправлении вывода, по флагу или по переменной окружения `NO_COLOR`.

#### Scenario: Вывод перенаправлен в файл
- **GIVEN** запуск с перенаправлением стандартного вывода
- **WHEN** утилита печатает отчёт
- **THEN** управляющие последовательности не выводятся

#### Scenario: Тихий режим
- **GIVEN** запуск с флагом тихого режима и запросом файловых отчётов
- **WHEN** утилита завершает работу
- **THEN** отчёт в консоль не печатается, а файлы записаны

### Requirement: Гистограмма распределения ассетов
Отчёт ДОЛЖЕН показывать распределение пакетов по худшему TFM выбранных ассетов, включая пакеты
без TFM-зависимых ассетов.

#### Scenario: Обзор состояния графа
- **GIVEN** таргет `net8.0` с 224 пакетами
- **WHEN** формируется гистограмма
- **THEN** видно, сколько пакетов отдают ассет ровно под `net8.0`, сколько `net6.0`,
  сколько `netstandard2.0` и сколько вовсе не имеют TFM-зависимых ассетов

### Requirement: Самодостаточный HTML-отчёт
HTML-отчёт ДОЛЖЕН быть одним файлом без внешних ресурсов, ДОЛЖЕН корректно отображаться при
ширине от 400 пикселей и ДОЛЖЕН поддерживать светлую и тёмную темы.

#### Scenario: Открытие без сети
- **GIVEN** сохранённый HTML-отчёт, перенесённый на другую машину без интернета
- **WHEN** файл открывают в браузере
- **THEN** страница отображается полностью: без загрузки шрифтов, скриптов и картинок извне

#### Scenario: Узкий экран
- **GIVEN** HTML-отчёт, открытый при ширине окна 400 пикселей
- **WHEN** страница отрисована
- **THEN** горизонтальная прокрутка страницы отсутствует, а широкие таблицы прокручиваются
  внутри своих контейнеров

#### Scenario: Тёмная тема системы
- **GIVEN** система с тёмной темой
- **WHEN** открывают HTML-отчёт
- **THEN** страница использует тёмную палитру, сохраняя различимость уровней находок

### Requirement: Интерактивный граф в HTML-отчёте
HTML-отчёт ДОЛЖЕН содержать граф зависимостей, разложенный по слоям глубины от проекта, с
подсветкой путей до находок, панорамированием, масштабированием и переключением объёма показа.

#### Scenario: По умолчанию показаны только пути до ошибок
- **GIVEN** таргет с 231 узлом в графе
- **WHEN** открывают HTML-отчёт
- **THEN** граф показывает только узлы на путях до ошибок, а переключатели позволяют развернуть
  его до всех находок и до полного графа

#### Scenario: Подсветка пути узла
- **GIVEN** отрисованный граф
- **WHEN** пользователь щёлкает по узлу
- **THEN** подсвечиваются все его предки и потомки, остальные узлы притухают, а сбоку открывается
  панель с деталями узла

#### Scenario: Фильтрация находок
- **GIVEN** список находок с фильтрами по уровню, TFM ассета и поиском по тексту
- **WHEN** пользователь снимает уровень «информация»
- **THEN** список перерисовывается, а счётчик показывает, сколько находок отображено из общего числа

### Requirement: Файлы графа для внешних средств
Утилита ДОЛЖНА уметь выгружать граф в формате Graphviz DOT и в формате DGML, с раскраской узлов
по уровню находки и выделением путей до находок.

#### Scenario: Рендер через Graphviz
- **GIVEN** записанный DOT-файл
- **WHEN** его обрабатывают командой `dot -Tsvg`
- **THEN** получается изображение графа с подписанными узлами и раскраской по уровням

#### Scenario: Открытие в Visual Studio
- **GIVEN** записанный DGML-файл
- **WHEN** его открывают в Visual Studio
- **THEN** узлы сгруппированы по таргетам, а категории задают раскраску и легенду

### Requirement: Машиночитаемый отчёт
JSON-отчёт ДОЛЖЕН содержать все находки, цепочки, рекомендации и советы фида в структурированном
виде, пригодном для обработки в CI.

#### Scenario: Разбор в конвейере
- **GIVEN** записанный JSON-отчёт
- **WHEN** его читает скрипт CI
- **THEN** доступны идентификаторы пакетов, уровни, TFM ассетов, глубины, цепочки и итоговые
  счётчики по уровням
