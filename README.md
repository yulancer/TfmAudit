# tfm-audit

Консольный анализатор графа зависимостей NuGet. Читает `project.assets.json` и для каждого
таргета проекта находит пакеты, чьи **выбранные ассеты относятся к более раннему поколению,
чем сам таргет** — например `lib/net6.0` под `net8.0` или `lib/net8.0` под `net10.0` — после чего
объясняет оператору, какая прямая зависимость их притащила и что нужно обновить.

Утилита собрана под **net6.0**, без единого `PackageReference`: используется только то, что есть
в net6 из коробки (`System.Text.Json`, `HttpClient`, `System.IO.Compression`, `System.Xml.Linq`).

## Зачем это нужно

При переводе проекта с net6 на net8 сам проект пересобирается под новый таргет, а вот граф
зависимостей — нет. NuGet при восстановлении выбирает **наибольшую папку ассетов, не превышающую
таргет**. Если у пакета есть `lib/net6.0` и нет `lib/net8.0`, под таргетом `net8.0` он молча отдаст
net6-сборку: ни ошибки, ни предупреждения сборки не будет. В результате в приложении на net8
оказывается слой библиотек, собранных под net6, net5, netcoreapp2.1 и netstandard1.x — со старыми
API-контрактами, старыми зависимостями и лишними пакетами-фасадами.

`tfm-audit` вытаскивает этот слой наружу и превращает его в план работ.

**Мультитаргетность ошибкой не считается.** Каждый таргет проверяется относительно себя, поэтому
проект с `<TargetFrameworks>net6.0;net8.0</TargetFrameworks>` и условными ссылками
(`Condition="'$(TargetFramework)'=='net6.0'"`) не даёт ложных срабатываний: расхождения между
таргетами — это норма, а не находка.

## Уровни находок

| Уровень | Когда | Что означает |
|---|---|---|
| **Ошибка** | ассет отстаёт от таргета на 2+ мажорных поколения (`net6.0` под `net8.0`, `netcoreapp3.1` под `net8.0`), либо подставлен ассет чужого семейства (.NET Framework под .NET Core) | пакет заметно старее таргета: тянет старые контракты и лишние зависимости |
| **Предупреждение** | ассет отстаёт на 1 поколение (`net7.0` под `net8.0`), либо `netstandard1.x`, либо у пакета есть `frameworkAssemblies` | требует внимания, но не критично |
| Информация | ассет `netstandard2.x` (формально совместим с любым современным .NET), либо устарели только MSBuild-ассеты (`build/net6.0/*.props`) | признак давно не обновлявшегося пакета |

Правило общее и не захардкожено под net6/net8: логика работает на любой паре
«таргет — ассет» внутри одного семейства, включая `net8.0` под `net10.0`.

## Сборка

```bash
dotnet build src/TfmAudit/TfmAudit.csproj -c Release
```

Одним файлом под конкретную платформу:

```bash
dotnet publish src/TfmAudit/TfmAudit.csproj -c Release -r win-x64 \
  --self-contained false -p:PublishSingleFile=true -o ./publish
```

В csproj стоит `<RollForward>LatestMajor</RollForward>`, поэтому собранная под net6 утилита
запускается и на машине, где установлен только более новый рантайм.

## Использование

```bash
# самый частый случай
tfm-audit ./src/MyApi/obj/project.assets.json

# папка проекта — assets найдётся сам; отчёты в файлы
tfm-audit ./src/MyApi -f net8.0 --md --html

# всё решение сразу, все форматы
tfm-audit . -r --all-formats -o ./artifacts/tfm

# спросить у NuGet-фида, до какой версии обновлять
tfm-audit ./src/MyApi --online --deep --md

# внутренний фид с авторизацией
tfm-audit ./src/MyApi --online \
  --source https://nuget.company.local/v3/index.json \
  --source-username ci --source-password "$NUGET_PAT"

# в CI: только ошибки, без вывода в консоль, ненулевой код возврата
tfm-audit ./src/MyApi --min-severity error --fail-on error --quiet --json
```

Полная справка — `tfm-audit --help`.

### На вход принимается

* `project.assets.json`;
* папка проекта (возьмётся `obj/project.assets.json`);
* `.csproj` / `.fsproj` / `.vbproj` (возьмётся `obj/project.assets.json` рядом);
* `.sln` или папка решения вместе с `-r` — будут найдены все `**/obj/project.assets.json`.

Важно: `project.assets.json` появляется после `dotnet restore`. Утилита читает результат
восстановления, а не сам csproj, поэтому видит именно то, что реально попало в сборку.

### Коды возврата

| Код | Значение |
|---:|---|
| 0 | успех |
| 1 | ошибка выполнения: файл не найден, некорректные аргументы, не разобрался assets |
| 2 | найдены находки уровня `--fail-on` и выше |

## Форматы отчётов

| Флаг | Файл по умолчанию | Что внутри |
|---|---|---|
| — | stdout | читаемый отчёт с ANSI-цветами: сводка, гистограмма TFM, план обновления, находки с цепочками |
| `--md` | `tfm-audit.md` | то же в Markdown — можно приложить к задаче или PR |
| `--html` | `tfm-audit.html` | самодостаточная страница: карточки, фильтры, послойный интерактивный граф, панель узла |
| `--json` | `tfm-audit.json` | машиночитаемо для CI |
| `--dot` | `tfm-audit.dot` | Graphviz: `dot -Tsvg tfm-audit.dot -o tfm-audit.svg` |
| `--dgml` | `tfm-audit.dgml` | открывается в Visual Studio (Architecture → Directed Graph Document) |

HTML-отчёт не тянет ни одного внешнего ресурса: ни CDN, ни шрифтов, ни картинок. Его можно
переслать в мессенджере и открыть без интернета. Граф по умолчанию показывает только пути до
ошибок (полный граф на 200+ узлов нечитаем), переключатели рядом дают «все находки» и «весь граф».

## Как читать вывод

Для каждой находки утилита показывает:

* **какой ассет выбрал restore** — с точным путём внутри пакета (`compile: lib/net6.0/Foo.dll`),
  чтобы вывод можно было проверить руками;
* **насколько он отстаёт** — в мажорных поколениях;
* **кто его притащил** — список прямых зависимостей проекта, из которых пакет достижим;
* **путь** — цепочка `A → B → C` от прямой зависимости до проблемного пакета. Обновлять надо
  первый элемент цепочки: транзитивную версию напрямую не поднять, кроме явного пина;
* **подсказку**, если пакет входит в состав рантайма (`System.Text.Json` на net6+) или является
  старым контрактом эпохи netstandard 1.x — такие ссылки обычно можно просто убрать;
* **совет фида** в режиме `--online`: минимальная версия, у которой уже есть ассет под ваш таргет.

Раздел «Что обновить» честно разделяет два случая:

* находка достижима **ровно из одной** прямой зависимости — её снимет одно обновление;
* находка достижима **сразу из нескольких** — она уйдёт только после обновления всех виновников,
  потому что каждый из них тянет свою копию.

Поэтому список отсортирован по влиянию (сверху те, у кого больше «эксклюзивных» находок), а не
подан как «минимальный набор»: минимального набора в таком графе не существует.

## Режим `--online`

Без флага утилита работает строго по `project.assets.json` и не обращается в сеть.

С `--online` для каждого проблемного пакета ищется минимальная версия, у которой есть ассет ровно
под целевой TFM. Источники берутся из `NuGet.config` (поднимаясь от папки с assets до корня диска,
плюс пользовательский конфиг; учитываются `<clear/>`, `disabledPackageSources` и
`packageSourceCredentials`) или задаются флагом `--source`. Поддерживается только NuGet V3
(`index.json`) через ресурс `PackageBaseAddress/3.0.0`.

Поддержка TFM определяется по `.nuspec` (группы зависимостей). Флаг `--deep` вместо этого читает
папки `lib/`, `ref/`, `runtimes/` прямо из `.nupkg` — точнее, но медленнее. Поиск бинарный
(поддержка TFM монотонна по версиям), поэтому на пакет уходит порядка 2·log₂(N) запросов.

`ProjectReference` в фиде не ищутся: это локальные проекты решения.

## Структура репозитория

```
src/TfmAudit/
  Cli/            разбор аргументов, поиск assets-файлов
  Model/          Tfm (парсер и компаратор TFM), модель project.assets.json и её чтение
  Analysis/       классификация ассетов, граф, атрибуция, рекомендации, база знаний о пакетах
  NuGet/          NuGet.config, клиент V3, подбор версий
  Reporting/      консоль, Markdown, JSON, HTML (шаблон в ресурсах), DOT, DGML
samples/          пример project.assets.json (мультитаргет net6.0 + net8.0; граф
                  настоящего проекта с обезличенными именами — внутренние пакеты
                  и фиды заменены на Contoso.*)
openspec/         спецификации и история изменений по процессу OpenSpec
```

## Проверка на примере

```bash
dotnet run --project src/TfmAudit -- samples/project.assets.json -f net8.0 --all-formats -o ./out
```

На вложенном примере (мультитаргет `net6.0` + `net8.0`, 231 узел в графе) под таргетом `net8.0`
находится 51 ошибка, 17 предупреждений и 60 информационных находок; ассет ровно под `net8.0`
отдают 74 пакета из 224.

## Известное ограничение сборки

Утилита разрабатывалась в окружении, где хосты Microsoft и `nuget.org` закрыты политикой, поэтому
таргетинг-пак `Microsoft.NETCore.App.Ref 6.0.x` скачать не удалось. Компиляция проверялась под
`net8.0` при `<LangVersion>10.0</LangVersion>` (уровень C#, соответствующий net6), с нулём
предупреждений; API-поверхность ограничена доступным в net6. **Первую сборку на машине с
net6-таргетинг-паком стоит прогнать отдельно** — см. задачу в
`openspec/changes/archive/2026-09-10-add-tfm-dependency-audit/tasks.md`.
